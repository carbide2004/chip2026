# PatientPheX：从官方数据重新建立实验体系

## 0. 定位与证据等级

目标：在模型参数不超过 10B、不能使用外部人工标注表型数据集的约束下，优化四项 F1 的等权平均，同时保留可复现性和论文证据。

- 官方规则与原始数据是起点；旧代码、README 分数、旧实验解释全部视为待验证材料。
- 本文的数据统计来自 `data/raw/PatientPheX-V1-A/`，未使用旧 `src/metrics.py`。
- 下述诊断统计不是交叉验证结果，也不是线上成绩。提议的模型尚未训练，收益均为待验证假设。
- 不删除旧方案。旧提交保留为历史对照，在新评测体系中复测后才决定是否复用。

## 1. 已核实的数据事实

| 项目 | 核查结果 | 对方案的影响 |
|---|---|---|
| 规模 | 80 篇训练文献、209 位患者、6027 个实体；A 榜 20 篇、53 位患者 | 小样本文档任务，不适合从头学习封闭 HPO 分类器 |
| 坐标 | 训练实体及患者 mention 的 offset/length/text 均能回溯到 passage 原文 | 保留原始坐标，不能重新拼接后直接生成 offset |
| 长度 | 训练文献字符数中位数 16048.5，最大 38364 | 按实际 tokenizer 统计长度；没有证据必须使用超长上下文模型 |
| 患者数 | 36 篇单患者、44 篇多患者，最多 14 位 | 单患者和多患者均需实质性的关系判断 |
| section 标注 | INTRO 1517、DISCUSS 1382、ABSTRACT 621、TITLE 60 个实体 | 任务1不能删掉背景章节、标题或摘要 |
| 特殊实体 | 否定 171、复合 69、无ID 109 | 必须支持格式，但优先级由错误分析决定，不能假设是主要瓶颈 |
| 空患者集合 | 12 位患者的关联集合为空 | 需要允许空输出，不应强制每位患者有表型 |
| 嵌套/重叠 | 40 对不同 span 存在重叠，另有16对同 span 标注 | 简单最长匹配、单层 BIO 并不完全覆盖标注结构 |
| 词典覆盖诊断 | 有效当前分支的阳性 mention-ID 单元中，3359/5804（57.9%）的完整 gold 文本能匹配对应 HPO 名称或同义词（小写、合并空白） | 这是 gold-span 条件下的词表覆盖率，不是实际 NER recall；必须有语义召回与边界学习 |
| 长尾 | 原始阳性概念统计中大量 ID 仅在单篇文章出现 | 采用 HPO 检索与候选重排，不依赖训练集固定类别 |

### 原始标注也存在噪声

- 发现格式不规范的 ID（如 `HP:000328`、`N`）、MESH ID、旧 ID、obsolete ID 和指定分支外 ID。
- association 原始列表共 2307 项，其中同一患者列表内有177个重复项，涉及70位患者。
- association 中33个字符串含分号，不能仅凭任务1的复合拆分说明推定任务2线上一定怎样处理。
- 在“仅将规范的 HPO 分号串拆分、患者内去重”的诊断口径下，有2171个关联单元，其中16个在阳性 gold entities 中找不到相同字符串。需要逐例检查，不能直接视为应补标的实体。
- 已抽查到具体冲突：PMC10553122 offset=9764 的 rhonchi 标为NO，全文该HPO仅这一处实体，但O1仍关联HP:0030831。这是需组织方确认的规则/标注不一致，不能自行断言阴性症状应进入关联答案，也不能静默改掉原答案。
- -1也不一定代表本体客观上无对应概念：样例包括 dysmorphic traits、hemogram，以及 low-set, cupped ears 中的 low-set。必须区分官方标注决策、上下文省略与本体真正缺失。

处理原则：保留原始文件不变；所有规范化产生派生视图及 provenance。评测视图和训练视图分离。禁止静默修复官方验证答案后将所得分数当官方可比成绩。

### 单患者快速路径的反证

诊断：仅在36篇单患者训练文章中，把全部阳性金标准实体概念直接分配给该患者。按上述分号拆分、集合去重口径，得到 Precision=0.5506、Recall=0.9904、Micro-F1=0.7078。

这不是模型性能，而是说明：即使实体已知，单患者文章仍包含大量不属于目标患者的表型。不能默认全部关联。

## 2. 第一阶段：可信数据与评测基础设施

### 2.1 不可变数据层

- 记录 ZIP、训练集、A榜输入、hp.obo 的 SHA256。
- 原始文件只读，不提交数据与凭证。
- 建立数据清单、ID 检查、重复检查、文档/患者主键检查、offset回溯检查。
- HPO 解析覆盖 name、synonym scope、definition、is_a、alt_id、obsolete、replaced_by、consider。
- 主ID和原始ID均保留；自动映射只能用于有明确依据的训练派生视图，并记录理由。
- 检查全文近重复文档；高度重复文档分到同一组，不能跨训练/验证。

### 2.2 保留坐标的中间表示

建议内部结构：

```text
Document -> Passage -> Sentence
Patient -> supplied anchors + candidate aliases + supporting evidence
Mention -> global span + original surface + candidate HPO IDs + assertion
Evidence -> patient + concept + occurrence span + context + confidence
Association -> patient + concept + aggregated evidence
```

- 实体 offset = passage.offset + passage 内的原始字符位置。
- 规范化文本只能用于检索，若用于抽取必须维护到原始字符的映射。
- 同一表面串多次出现不能用全文第一个 find() 定位。
- 复合实体保留一个原始 span，允许多个概念；规范化的展开短语只是内部检索形式。
- 否定属于具体 occurrence；某处被否定不能全篇删除同一 HPO。
- 任务1的相关性和任务2的相关性分开处理：背景章节有实体，不代表属于给定患者。

### 2.3 新评测器与问题清单

优先索取官方 evaluator；未获得前，将线上一致性标为未确认。

独立测试至少覆盖：精确边界、偏移差1、错误ID、重复预测、一对一匹配、复合实体部分命中、gold -1、pred -1、否定、空集合、缺失患者、额外患者、同ID多次出现、alt_id、非评价区域。

待向官方确认：

1. gold 是有效 HPO 时，pred=-1 是否可匹配？不能把本地宽松实现当官方规则。
2. 任务2中复合字符串是否拆分？
3. alt_id/obsolete/异常标注怎样评价？
4. 评价区域的精确定义，尤其标题、摘要、图表。
5. 双空集合等边界情况及额外文档/患者的处理。
6. 实体标NO却出现在患者association中的案例，是标注错误还是关系标签另有语义？

注意：官方说非评价区域预测不计分，不能笼统断言参考文献预测一定产生FP。也不能把“正文”机械解释为 BioC type=body。

## 3. 验证设计

### 推荐方案

- 从80篇中按文档/近重复文档组划分：64篇开发池，16篇锁定验证。
- 在64篇内部建立4折；快速实验先用固定一折，候选胜者再跑全部4折。
- 对单/多患者、篇幅、表型数量、特殊实体分布做粗粒度平衡；不追求每个长尾HPO分层。
- 锁定16篇不用于阈值、Prompt、规则或缩写表调整。定稿时只打开一次；若继续使用它调参，不再称其为独立验证。
- 最终配置确定后用全部80篇重训，生成 A/B 预测。
- 训练语料衍生词典、示例检索、hard negatives、SFT样本都只来自当前训练fold。
- HPO属于允许使用的公开知识，可跨fold共享。

每次实验记录：数据划分hash、模型revision、代码commit、配置、种子、四项F1、P/R、耗时、显存、逐文档预测及证据。

除总分外，报告单/多患者、已见/未见HPO、缩写、否定、复合、无ID、长文档、section切片。最终比较采用文档级配对bootstrap，患者不独立重采样；关键训练方案补多个种子。

## 4. 推荐技术主线

```text
保留坐标的文章切块
  -> 高召回表型span候选
  -> HPO词法/语义候选检索
  -> 上下文重排、边界与否定判断
  -> 患者别名和章节证据组织
  -> 患者-概念证据集合判断
  -> 分任务校准、去重、提交校验
```

### 4.1 表型span识别

建立三条可分离的候选来源：

1. HPO名称/同义词词典：强可解释baseline。
2. 仅用当前训练fold训练的生物医学编码器span模型：建议先选一个合规预训练编码器，如PubMedBERT，使用span头覆盖重叠。
3. 不超过10B模型的局部原文抽取：先作对照/难例补召回，不默认每段多轮调用。

编码器初始窗口512 tokens、stride128；最终参数按实际token长度和边界跨窗率校准。不要将这些初始值解释为已验证最优。

LLM只返回输入中的原文span或候选编号，不让它凭空编造字符偏移。使用确定性校验和重复出现消歧，无法对齐则拒绝输出。

### 4.2 HPO检索与重排

- 词法检索（exact/synonym/BM25或字符相似度）与向量检索并行召回，RRF合并。
- 可以比较SapBERT与一个替代生医编码器，但要先审查其权重来源及外部训练数据的合规性。
- Top-K先试5/10/20；先测gold-span条件下Recall@K，再测端到端。
- 候选卡包括名称、定义、同义词、父节点，必要时相邻混淆概念。
- 重排输入是surface+上下文+候选卡；输出候选编号、多选或NONE，不自由生成HPO字符串。
- 不输出上位概念闭包：赛事按精确ID评价，上位近似不是TP。
- 将“不是表型”与“是表型但HPO无匹配”分开，只有后者可以走-1。
- 词典、向量、重排分数分别校准，不复用一个全局0.92阈值。

### 4.3 患者关联：证据集合，而非最近距离或单次出现

为每个患者-概念候选对收集：

- 所有相应表型occurrence，而非全篇第一个；
- 官方患者anchors及有依据的别名/谱系编号；
- 相关句、相邻句、段落标题；
- 其他患者及亲属指代，否定与时间信息。

语义中间标签可区分：目标患者、其他个体、泛化背景、否定、不确定。最终输出正关联或不输出；同一概念允许属于多位患者，不能做强制互斥分配。

关键监督限制：association只给患者-概念集合，不提供每个mention的患者标签。不能因为(p,h)为正，就把h的全部mentions都标成p的阳性证据。例如PMC10313222的P1关联HP:0000819，该概念的多处mention却包括背景、家族史及母亲诊断。主体归属与肯定/否定还应分开建模；对原始关联与否定冲突的样本打上噪声标记，不伪造确定的mention标签。

推荐训练单位是“patient + concept + evidence bag”，用bag级标签监督。可先做LLM约束分类，再比较轻量集合聚合器/多实例学习。负例由同篇其他患者、背景段、否定、近邻但不同主体构造；自动生成负例需抽检，避免把漏标当确定负例。

最终关系模型还应看到out-of-fold预测候选，而不只见gold实体，以适应任务1的真实噪声。

单患者也进行关联判断。距离只作为特征和检索优先级，不能成为硬裁剪条件。空集合是合法输出。

### 4.4 证据补召回

关系模块怀疑存在遗漏时，允许在原文中定向补查候选表型；必须定位到文本证据并重新标准化。不能根据疾病常识“补出”文章没有表达的患者症状。

不要求两个输出机械地完全一致，但要求实体和关联有可追溯的原文支持。

## 5. 分阶段实验矩阵

| 实验 | 改变量 | 主要问题/验收指标 |
|---|---|---|
| E0 | 数据审计、评测单元测试、固定划分 | 无坐标漂移；异常有清单；评价歧义单独记录 |
| E1 | 新词典baseline；若可获取则复现官方PhenoTagger+Qwen3-8B | 建立可复现起点；官方指定HPO及权重合规性可验证 |
| E2 | gold span + 不同HPO检索器 | Recall@5/10/20、Top1准确率、未见概念性能 |
| E3 | span模型、词典和受控LLM候选分别/联合 | span exact F1、重叠span召回、任务1两个F1 |
| E4 | gold实体 + 不同关系策略 | 隔离关联瓶颈：距离、证据分类、证据集合/MIL对照 |
| E5 | predicted实体 + 同一关系模型 | 测真实端到端差距；OOF候选训练是否改善 |
| E6 | 固定最佳架构，比较base prompt与QLoRA | 微调是否真有跨文档收益，不以训练loss判断 |
| E7 | 分别加入缩写、复合、-1、困难负例、补召回 | 单因素增量及代价；无收益就不进入最终模型 |

Oracle实验只用于定位瓶颈，不冒充可部署成绩。A榜提交不代替本地验证，不因线上一次微涨就宣布创新成功。

## 6. 值得验证的创新方向

### A. 患者感知的多证据集合学习（最高优先）

用patient-concept级标签监督多个occurrences的证据聚合，避免制造错误mention标签。保留主体、section、否定信息，同一概念可多患者共享。

消融：首个mention、最近mention、全证据分类、bag/MIL；重点看多患者Macro-F1和背景FP。

### B. HPO近邻困难负例与层级消歧

负例不是随机无关ID，而是候选检索误召回、父子/兄弟概念、部位/程度相似概念。训练模型回答“哪一个被原文支持”，而非泛泛医学相似。

消融：随机负例 vs 检索负例 vs 层级负例；看gold-span标准化准确率及未见ID表现。层级信息只辅助判别，不扩大最终预测集合。

### C. 临床展开与原始span解耦

复合省略和缩写先在内部展开，再检索HPO；输出仍保留原始跨度。例如协调省略可能对应多个HPO，而不是多个虚构的原文span。

消融：直接短语检索 vs 上下文展开检索；分别统计复合与普通实体，防止展开导致过度多选。

### D. 按不确定性分配推理预算

高置信词典匹配、向量/词法一致且主体明确的候选直接进入轻量路径；缩写、候选接近、多患者冲突等进入8B判别。

消融：全量LLM vs 路由推理，比较四项F1、调用量和时间。先验证校准，不能将低召回规则包装成高效路由。

以上是适合本赛题的研究假设，不宣称未经文献检索验证的学术首创。优先A+B，C作为特殊现象处理，D在质量稳定后推进。

## 7. 算力、合规和时间安排

当前环境检测到RTX 5090，约32GB显存。建议小编码器训练+Qwen3-8B共享判别模型；先检查PyTorch/CUDA/attention实现兼容性，再用4-bit QLoRA、1–4K token证据包、小microbatch做显存实测。不承诺未测训练时长。

所有模型记录参数规模、revision、license和公开来源；模型量化不会减少名义参数量。多个模型/ensemble的10B如何计算、是否允许更大教师模型生成训练材料，未确认前采取保守方案，不使用超限教师或外部人工表型标注。

若实际还有约10个开发日，可安排：

- 第1–2天：数据审计、官方问题清单、评测测试、划分和baseline。
- 第3–4天：span候选、HPO检索和标准化诊断。
- 第5–6天：患者别名、证据集合、oracle/端到端关联对照。
- 第7–8天：一次有依据的QLoRA与困难负例实验，完成消融。
- 第9天：多折复核、锁定验证、冻结主方案。
- 第10天：全80篇重训、批处理/提交校验、结果缓存、回退方案与技术报告。

按实际阶段和组织方最新通知调整，不根据网页旧倒计时推定当前日期。不使用A/B预测伪标签参与训练，除非官方明确允许。
